## 요약

Kubernetes 1.37을 지원하지 않거나 EOL이던 시스템 컴포넌트를 먼저 올린 뒤, 제어 플레인을 `v1.36.4 → v1.37.1`로 올리고 워커 2대를 `v1.37.1` 노드로 교체했다. 워커 교체 중 prod honami가 약 1분, Argo CD UI가 약 3분 503을 반환했다.

## 영향

- 16:21:30 ~ 16:22:27 `mllm.kr` HTTP 503. replicas 1인 honami가 비운 노드에서 새 노드로 옮겨가는 동안이다.
- 16:29:54 ~ 16:32:51 `argocd.sqr.kr` HTTP 503(첫 호출은 연결 실패). argocd-server가 새 노드에서 이미지(650 MB)를 받는 동안이다.
- dev `notification-backend`가 새 노드에서 이미지(830 MB)를 받느라 약 3분 동안 Ready가 아니었다.
- 컴포넌트 업그레이드와 제어 플레인 업그레이드 중에는 2초 간격 호출 기준으로 실패가 없었다.

OKE가 2026-11-17부터 `v1.37.1`을 운영용으로 지원한다. 작업 전 호환성 확인 결과:

저장소 밖에서 한 작업:

- Envoy Gateway chart를 올리기 전마다 같은 버전의 `gateway.envoyproxy.io` CRD를 gateway-crds-helm으로 렌더링해 `kubectl apply --server-side --force-conflicts`로 적용했다.
- Argo CD를 `helmfile diff` 확인 후 `helmfile apply`로 올렸다.
- Terraform state를 저장소 밖 비공개 경로에 백업했다.
- 제어 플레인 apply 중 node pool 변경이 `409-Conflict, Cannot update Kubernetes version which has already been set by OKE worker node image`로 실패했다. 제어 플레인은 `v1.37.1`로 끝난 상태였고, `oke_image_name`을 `Oracle-Linux-9.8-aarch64-2026.10.16-0-OKE-1.37.1-2067`로 바꿔 node pool을 다시 apply했다.
- node pool을 3대로 늘려 `10.20.1.20`을 만들고, `10.20.1.108`은 크기를 유지한 채 삭제해 `10.20.1.80`으로 대체했다. 마지막 `10.20.1.58`은 `--is-decrement-size true`로 삭제했다.
- drain 중 External Secrets webhook이 옮겨가는 동안 `external-secrets` 앱이 Server-Side Diff의 webhook 호출 실패로 `Unknown`이 되어 hard refresh로 되돌렸다.
- 로컬 `kubectl`을 1.37.2로 올리고 `kubeconform`, `helmfile`을 설치했다.

## 결정 사항

- cert-manager는 Kubernetes 1.37을 지원 목록에 올린 릴리스가 없어 1.21.3으로 진행했다. 1.22가 나오면 올린다.
- Argo CD chart 10.x 기본값대로 NetworkPolicy가 생긴다. CNI가 Flannel이라 적용되지는 않는다.
- Datadog Agent 7.78부터 기본으로 켜지는 service discovery는 system-probe 컨테이너를 추가하므로 끈다.
